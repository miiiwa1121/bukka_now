## 2026-10-11: コア要件とユーザー体験仕様の策定

> **置換済**: 1（クイズ形式）と 4（7問構成）は [クイズ入力方式・結果表示・設問数仕様の刷新](#2026-10-11-クイズ入力方式結果表示設問数仕様の刷新) で置き換えた。カテゴリ別レーダーチャートは実装していない。2（総合スコア・タイプ診断）と 3（登録不要・SNS シェア）は現行仕様でも有効。

- **決定内容**:
  1. **クイズ形式**:
     - 4択選択式、ニアピンスライダー式、過去比較クイズを組み合わせた「ハイブリッド型」を採用。
  2. **診断・スコアリング仕様**:
     - 総合スコア（0〜100点）の算出。
     - 物価感覚タイプ診断（相場のズレ傾向をキャラクター/タイプ分類）。

     - 全体統計比較（「世間の予想平均」vs「あなたの予想」vs「実際の公的相場価格」）の提示。
  3. **利用形態・認証**:
     - ユーザー登録不要（ゲスト即プレイ）。
     - クイズ結果のSNS（X等）シェア機能を第一級の体験として組み込む。
  4. **セッション設問数**:
     - 1回の診断につき「7問」構成とする。各形式・各カテゴリを網羅し、飽きずに2分程度でしっかり診断できるバランス。

## 2026-10-11: クイズ入力方式・結果表示・設問数仕様の刷新
- **決定内容**:
  1. **回答入力方式の統一**:
     - すべてのクイズの答えは「数字（円）」に統一。
     - 入力UIは「0〜9の数字キー」および「OKボタン」（テンキーパッド形式）に統一。4択やスライダーは廃止し、電卓風のダイレクト入力とする。
  2. **結果画面の棒グラフ（全体ユーザー分布）**:
     - 全体ユーザーが選んだ数字の分布（度数棒グラフ / ヒストグラム）をリアルタイムに更新・表示。
     - 棒グラフ内に「あなたの選択（ユーザー回答）」と「実際の正解（公的価格）」のマーカーを統合。
  3. **スコア指標（パーセンタイル表示）**:
     - 単なる点数だけでなく、「上位何%の意識スコア（例: 上位 8.5%）」を主要な診断スコアとして表示。
  4. **絵文字の完全排除**:
     - システム全体・UI・テキスト・診断結果・バッジ等から絵文字を一切排除。ソリッドで洗練されたフィンテックUIとする。
  5. **設問数の可変対応（10〜100問、10問単位）**:
     - ユーザーが開始前に「10問〜100問（10問刻み: 10, 20, 30, ... 100問）」を選択可能にする。
     - 100問規模の物価マスターデータ（食料品・外食・日用品・インフラ・レジャー・家電等）を網羅。

## 2026-10-11: UIデザインの「unpis.net（イラストレーターunpis風）」への一新
- **背景・経緯**:
  - たべっ子どうぶつ風は装飾過多だったためリジェクト。
  - イラストレーター unpis 氏の公式サイト（https://unpis.net/）の洗練されたミニマリズム、温かみのあるエクリュ（生成り）の紙質感、均一な2pxの黒アウトライン、朱赤（ポピーレッド）を中心とするフラットな差し色、クリーンな余白美を取り入れたモダンイラストレーション調のUIへ一新する。
- **決定内容**:
  1. **カラーパレット**:
     - ベース背景: 穏やかで清潔なエクリュ・ライトグレー（`#f2ede4` / `#f6f4ee`）。
     - カード・パネル: ピュアホワイト（`#ffffff`）。
     - ライン・文字: 墨黒（`#191919` / `#222222`）。
     - アクセントカラー:
       - ポピーレッド（朱赤）: `#eb4634`（メインアクション、ハイライト）
       - コバルトブルー: `#1877f2`（あなたの選択）
       - リーフグリーン: `#25a25a`（正解相場）
       - マスタードイエロー: `#f5a623`
  2. **ラインワークとシャドウ**:
     - すべてのカード、ボタン、テンキー、バッジに **均一で滑らかな 1.5px〜2px のソリッド黒線（`border: 2px solid #191919`）** を適用。
     - 影はボカシではなく、フラットなオフセット影（`box-shadow: 3px 3px 0 #191919`）。
     - ボタン押下時に `transform: translate(2px, 2px); box-shadow: 1px 1px 0 #191919;` と沈み込む小気味よいインタラクション。
     - **置換済**: 影と、押下時の沈み込み（translate）は「UI 全体から影を削除」の決定で撤廃した。
  3. **タイポグラフィ**:
     - Google Fonts `Outfit` ＆ `Noto Sans JP` による洗練された幾何学モダンサンセリフ。
     - 見出しやラベルはすっきりとした小文字・ミニマルな日本語。
  4. **テンキー＆棒グラフ**:
     - テンキー: 白背景＋2px黒線＋フラットオフセット影。数字はボールドな黒文字。CとBSは落ち着いたアクセント、決定（OK）はポピーレッド。
     - 棒グラフ: 2pxの黒枠で囲まれたミニマルなフラットバー（青、緑）。
  5. **絵文字ゼロとシンプル is best の厳守**:
     - 絵文字は一切使用しない。幾何学的で洗練されたアートポスターのような佇まい。

     - グラフ上部に「回答」「正解」「平均値」「重なり（シマシマ）」の四角いスウォッチ付き凡例を配置し、初見のユーザーでも瞬時に色とパターンの意味を把握できるように設計。

## 2026-10-11: 診断結果画面の構成（ADR-009〜012）

> ADR-009〜012 は、結果画面の「固定スコアカード＋3面スライドボード」構成に関する一連の決定。

- **ADR-009: 診断結果画面におけるスコアカードの独立固定化と下部スライドラックの分離**
  - **背景**: 診断サマリー、1単位プロット棒グラフ、物価推移図の3面を横スライドで切り替える構成において、スコアヘッダー（上位XX%、総合スコア、タイプ、辛口コメント、シェア/コピー/リトライボタン列）を各スライドカード内に重複配置するのではなく、タイトルと同様に画面上部に独立した1つの固定カードとして常駐させ、下の出題別データセクションのみを横スライドさせる設計に移行。
  - **決定内容**:
    1. **独立スコアカード（`.result-independent-score-card`）の新設**:
       - スライドラック（`.whiteboard-track-viewport`）の外側、タイトルヘッダー直下に配置。
       - 横幅を `--card-width: min(760px, calc(100vw - 120px))` とし、下の各スライドカードと外枠・左右余白・内部パディングを1ピクセル単位で完全一致。
    2. **スライドボードの責務純化**:
       - スライド面1（回答分布・統計）、面2（1単位プロット棒グラフ）、面3（物価推移図）からは重複していたスコアヘッダーを除去し、出題別の見出し（`result-section-header`）から始まるシンプルな構造に統一。
       - これにより、ユーザーは画面上部で常に自身のスコアと結果アクションを俯瞰しながら、下部の出題別詳細データのみを赤丸特大ナビボタン（`→` / `←`）でスムーズに横スライド探索できる。

- **ADR-010: スワイプ/ドラッグ画面切り替え・全設問カードのサイズ完全統一・物価推移折れ線グラフ化**
  - **背景**:
    1. 矢印ボタンクリックだけでなく、スマホでのタッチスワイプやPCでのマウスクリック＆ドラッグでも直感的に3枚のボードを切り替えたい。
    2. サマリー、1単位プロット棒グラフ、物価推移の3面で、各設問（Q1〜Q10）のカードサイズ・インデント・ヘッダー位置が微妙に異なっていたため、横スライド時にレイアウトが揺れていた。
    3. 物価推移図をタイムラインゲージから、より視認性と説得力の高い「折れ線グラフ（Line Chart）」に進化させたい。
  - **決定内容**:
    1. **スワイプ / ドラッグによる画面切り替えの導入**:
       - `onTouchStart`, `onTouchEnd`, `onMouseDown`, `onMouseUp` ハンドラーをスライドラックに実装。
       - `touch-action: pan-y;` を設定し、縦スクロール操作を妨げることなく、横方向のフリック・スワイプ（40px以上かつ水平優位）のみを滑らかに検知して面を切り替える直感的なジェスチャー操作を実現。
    2. **全設問カードの構造・サイズ・インデントの完全統一**:
       - 共通レイアウトクラス（`.unpis-question-card`、`.unified-card-header`、`.unified-metrics-grid`、`.unified-chart-container`、`.unified-note-text`）を新設。
       - 3面すべてで、設問カードの外枠、内部パディング（`1.5rem`）、ヘッダー（Q番号・カテゴリ・タイトル・回答者数）、メトリクス数値ボックス（4〜5カラム）、グラフ領域、フッター注記を1ピクセル単位で同一構造化。
       - 横スライドした際にカードの骨格がまったく揺れず、中央のグラフ領域のみが心地よく切り替わる洗練されたUIを実現。
    3. **物価推移のSVG折れ線グラフ（Line Chart）化**:
       - 各設問の過去基準相場（2020年）から中間年（2022年、2024年）を経て現在公的相場（2026年）に至る推移を、力強い墨黒ソリッドライン＋ウォームグラデーション塗りで描画。
       - 2026年の位置に「公的相場（正解）」「世間平均予想」「あなたの回答」のプロットピンおよび吹き出しタグを配置し、現在相場との乖離点線を明示。

## 2026-10-11: カード間ナビボタンをスライドレール内に配置し、カードと一緒にスライドさせる
- **背景**: ボタンはカードのスライドと一緒に動く UX にしたい。ただし、固定表示の上部スコアカードの上を横切ってはいけない。
- **決定内容**:
  1. ナビボタンを、画面固定（`position: fixed`）ではなく、スライドレール内の「カードとカードの間の隙間」に置く。間隔0（サマリーと詳細の間）と間隔1（詳細と物価推移の間）に1つずつ。レールの一部なので、カードと同じ距離・同じイージングで自然にスライドする。
  2. ボタンの縦位置は `position: sticky` で、スクロール中は画面の縦中央に留める。ボタンの移動範囲はレール（下のカード群）の高さに限られるので、上部スコアカードとは重ならない。初期表示では、下のカード群の上端の横に表示される。
  3. ボタンの表示は、隣接するボードのどちらかを表示中のときだけにする。左側のボードを表示中なら「→ 右のボードへ」、右側のボードを表示中なら「← 左のボードへ」。向きと行き先が変わるときは、中身をフェードインで切り替える。
  4. sticky を効かせるため、`html, body` とスライド関連コンテナの横はみ出し抑止を `overflow: hidden` から `overflow-x: clip` に変更した。`hidden` はスクロールコンテナを作り、sticky を無効にするため。

## 2026-10-11: クイズの正解・推移データを小売物価統計調査（東京都区部）に一本化
- **背景**: 旧マスター100問の正解価格は出典を確認できず、統計と大きく食い違うものがあった（例: 米5kg 2,880円 → 統計では2025年平均 4,928円）。推移も「2020年の1点＋計算した中間年」だった。開発者から「正当性を正確にし、確認できない問題は廃棄して入れ替える。推移はできるだけ昔（1940年代〜）から見たい」と依頼された。
- **決定内容**:
  1. **出典は総務省「小売物価統計調査」だけにする**。正解は東京都区部の **2025年平均価格**（確定している最新の年平均）。郵便・NHK受信料・新聞・映画の5問は全国統一価格。統計で確認できない価格（特定チェーンのメニュー価格・テーマパーク料金など）は出題しない。
  2. **地域は東京都区部**: 全国平均の小売価格は公表されておらず、1950年までさかのぼれる長期系列が東京都区部だけのため。設問文の下に「東京都区部・2025年平均（総務省 小売物価統計調査）」と前提を表示する。
  3. **推移は1950年から**: 公的な小売価格の長期系列は1950年（昭和25年）からで、1940年代は戦時統制・闇価格の時期で、一貫した統計がない。1950〜2010年は長期時系列表、2011〜2025年は年報を使い、実データだけで描く（補間値は使わない）。
  4. **系列のつなぎ方**: 重さ・容量の違いは比例換算してつなぎ、品物の種類が変わった時期（例: 袋めん→カップ麺、ロース→バラ）や換算できない単位の切り替わり（重さ→個数）より前は使わない。当時の調査銘柄が現在と異なる場合はコラムに注記する。判断は品目ごとに銘柄の変遷を目視で確認して `scripts/quiz-data/candidates.py` に記録する。
  5. **問題数は100問を維持**: 約130品目の候補から、確認できないもの（銭湯の料金、電気代など）、品物の変遷で比較期間がほとんど残らないもの（しょうゆ、ようかん）、単位が不自然なもの（1kgあたりのマヨネーズ等）を外して100品目にした。
  6. **問題 ID を `s` ＋ 銘柄符号に変更**（例: `s1001`）: 中身が別の問題になるため、本番 D1 の旧問題（`q1`〜`q100`）の回答履歴と混ざらないようにする。
  7. **マスターは生成物にする**: `src/data/quizMaster.ts` は `scripts/quiz-data/run.sh` で生成し、手で編集しない。別の作業ディレクトリで最初から再生成し、同一の内容になることを確認済み。

## 2026-10-11: ホスティングを Cloudflare Pages から Workers（Static Assets）に移行
- **背景**: 当初は技術スタックを「Cloudflare Pages / Workers」と併記したまま、Pages ＋ Pages Functions で実装していた。Pages を選んだ明確な理由は記録されていなかった。Cloudflare は新規プロジェクトには Workers（Static Assets 付き）を推奨している。
- **決定内容**:
  1. 静的配信は Workers Static Assets（`dist/`）、API は Worker（`server/index.ts` が Hono アプリを default export）にする。Pages Functions のエントリ `functions/api/[[route]].ts` は削除した。
  2. `assets.run_worker_first = ["/api/*"]` とし、Worker が起動するのは API だけにする。静的アセットのリクエストで Worker の呼び出しを消費しない。
  3. `not_found_handling = "single-page-application"` で、存在しないパスは `index.html` を返す（Pages の既定の挙動に合わせた）。
  4. `bukka-now.miiiwa.com` は Worker の Custom Domain として `wrangler.toml` の `routes` で管理する。`bukka-now.pages.dev` は使わなくなる。
  5. デプロイは引き続き手動（`npm run deploy` → `wrangler deploy`）。Pages で Direct Upload プロジェクトを Git 連携に変えられなかった制約はなくなる。
  6. D1 `bukka-now-db` とそのデータはそのまま使う（アカウント直下の独立リソースのため）。
- **理由**: Workers は Cloudflare の今後の機能追加の対象であり、静的配信と API を1つの `wrangler.toml` と `wrangler deploy` で管理できる。Hono アプリはそのまま Worker として動くため、アプリコードの変更は不要だった。

## 2026-10-11: 設問を普段の買い物で目にする単位にする
- **背景**: 統計の単位をそのまま使ったため「もやし（1kg）」「キャベツ（1kg）」「マヨネーズ（1kgあたり）」のような業者向けの単位の設問が多く、一般の利用者には相場が分からなかった（開発者の指摘: 「もやし一袋は分かるが1kgは分からない」）。
- **決定内容**:
  1. 設問は **1袋・1本・1パック・1杯・1回** など普段の買い物で目にする単位で書く。肉や魚は店頭の値札と同じ **100g** を使う。設問文は「〇〇はいくら？」の形にする。
  2. 統計が重さ単位の品目は、**量が客観的に決まるものだけ** 身近な量に換算し、設問に量を明記する（もやし1袋＝200g、木綿豆腐1丁＝300g、食パン1斤＝340g（包装食パンの表示ルール）、焼きそば3食入り＝麺450g（調査銘柄の規格））。
  3. **1個の重さが決まらない野菜・果物（キャベツ1玉、だいこん1本、りんご1個など）は出題しない**。統計の1kgあたりの価格から1個の値段を出すと推測値になり、正確さの方針に反するため。
  4. 空いた枠は、統計がもともと包装単位で調べている身近な品目で埋める（バーモントカレー、のりたま、焼肉のたれ、パック寿司、回転ずし1皿、ポカリスエット、リポビタンD、ジップロック、トミカなど）。
  5. 包装単位の品目は、**内容量・入り数が変わった年より前は使わない**（重さで比例換算しない）。内容量を減らした実質値上げを、換算で打ち消してしまわないため。
- **影響**: 推移が1970年以前までさかのぼれる問題は47問→24問に減った（2010年以前までなら42問）。包装商品の多くは2011年以降に調査が始まったため。正確さと身近さを優先した。
- **問題 ID**: 身近な量に換算した品目（食パン・焼きそば・もやし・豆腐）は、ID に量を付ける（例: `s1407-200g`）。前回（1kg単位）で本番に蓄積された回答と尺度が違うため、平均・分布に混ざらないようにする。それ以外で前回と同じ ID の68問は、正解の値が完全に一致する（同じ品目・同じ単位）ことを確認し、回答履歴を引き継ぐ。

## 2026-10-11: 採点式を「比率で3倍・3分の1で0点」に変える
- **決定内容**（開発者の判断）:

  2. 未回答は0点、総合スコアは出題全問の平均（変更なし）。相対誤差率とバイアスの定義も変えない。

- **理由**: 旧式（相対誤差40%で0点）は、実ユーザーの回答11件で平均23点・6件が0点と厳しすぎた。比較した5案のうち、この式は同じ11件で平均52点・0点1件で、相場観の差も点数に残る。
- **未決定**: タイプ判定（80点以上で「相場マスター」）と辛口コメントの点数帯。新しい式では生成データの60%が80点以上になる。

## 2026-10-12: PC のクイズ画面をスクロールなしで1画面に収める
- **決定内容**（開発者の依頼）: PC（幅641px以上）のクイズ画面を、スクロールせずに回答できるようにする。
  1. 横に2列にする。左の列に設問とディスプレイ（回答予想額）、右の列にテンキーと決定ボタン。ディスプレイは決定ボタンの高さに下端をそろえる。
  2. キーと決定ボタンの高さは、画面の高さに合わせて 40〜60px で伸び縮みさせる（`--key-h: clamp(40px, (100vh - 380px) / 5, 60px)`）。

- **理由**: 縦1列のままではページの高さが約1,020px あり、1920×1080 の画面でもスクロールが必要だった。縦に詰めるだけでは、ブラウザの表示領域が600px前後のノート PC に収まらない。
