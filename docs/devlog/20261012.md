# 開発ログ 2026-10-12

### 1. スマホの面切り替えを、画面の左下・右下に固定したボタンにする
- **依頼内容**: 前日（20261011 #64）に入れた上部固定のタブ（サマリー / 詳細データ / 物価推移）をやめ、画面の左下・右下に固定して最前面に置く。形は U 字を横にした形。
- **実装内容**:
  - `ResultDashboard.tsx`: タブを `renderEdgeNav()` に置き換えた。左下 = 前の面、右下 = 次の面。行き先がない側は `is-hidden` で画面外へ引っ込める。引っ込む間に文字が変わらないよう、そのときは端の面の名前（左ならサマリー、右なら物価推移）のままにした。
  - `src/index.css`: `.board-tabs` を削除し、`.board-edge-nav` / `.board-edge-btn` を追加（`position: fixed`、`bottom: 1rem + セーフエリア`、`z-index: 2147483647`、端側の枠線なし・内側の角丸 `9999px`）。結果画面のときだけ `.app-container:has(.board-edge-nav)` でページ末尾に余白を足した。
- **検証**: 375×667 で結果画面を撮影。サマリーでは右下だけ、詳細データでは左右両方、物価推移では左下だけ出ることを確認。最下部までスクロールしても、もう一度挑戦する・フッターがボタンに隠れない。`tsc -b` が通った。
- **気になる点**: ボタン（高さ52px）はカードの左下・右下の一部に重なる（グラフの下端など）。スクロールすれば見えるので、そのままにした。

### 2. PC のクイズ画面をスクロールなしにする
- **依頼内容**: PC でもクイズ中にスクロールしないで済むようにしてほしい（スマホ版は画面に収まっている）。
- **調査**: 表示領域 1280×600・1366×650・1440×780・1920×950 で計測。どれもページの高さが 1,021px で、スクロールが必要だった。縦1列のまま詰めても600px前後には収まらないため、横に2列にした。
- **実装内容**:
  - `NumberKeypad.tsx`: テンキーと決定ボタンを `.numpad-keys-wrap` で包んだ（PC で右の列にまとめて置くため）。案内文の「下記の」を削除（PC ではテンキーが右にあるため）。
  - `App.tsx`: クイズのカードに `quiz-card` クラスを追加。
  - `src/index.css`: `.numpad-keys-wrap` の基本スタイル（縦並び、間隔は親と同じ）と、末尾に「PC のクイズ画面」セクション（641px以上）。カードを CSS Grid の2列にし、`.numpad-container` は `display: contents` にしてディスプレイとテンキーを別々の列に置いた。キーの高さは `--key-h` で画面の高さに合わせる。`.app-container:has(.quiz-card)` でヘッダー下・ページ下の余白を詰めた。
- **検証**: 上の4サイズと 768×900 で、ページの高さが表示領域と同じ（スクロールなし）。1280×600 ではキー43px、1440×780 以上では上限の60px。スマホ（375×667・320×568）の計測値は変更前と同じ。`npm run build` が通った。lint の警告は以前と同じ7件。
