# クイズデータ・診断ロジック仕様書（Quiz Data & Scoring Logic）

`bukka_now` で出題する100問のマスターデータと、診断アルゴリズム（スコア、パーセンタイル、回答分布、タイプ判定）を定義します。
実装は `src/data/quizMaster.ts`（データ）と `server/scoring.ts`（ロジック）です。

---

## 1. マスターデータ

### 1.1 出典と基準

- **出典**: 総務省統計局「小売物価統計調査（動向編）」
  - 1950〜2010年: [主要品目の東京都区部小売価格（長期時系列）](https://www.stat.go.jp/data/kouri/doukou/3.html)（`kubu_chouki.xls`）
  - 2011〜2025年: [e-Stat](https://www.e-stat.go.jp/stat-search/files?page=1&layout=datalist&toukei=00200571&tstat=000000680001&cycle=7&tclass1val=0) の年次ファイル「調査品目の月別価格及び年平均価格」「全国統一価格品目の価格」
- **正解**: 東京都区部の **2025年平均価格**（確定している最新の年平均）。全国一律料金の品目（郵便・NHK受信料・新聞・映画）は全国統一価格。
- **地域を東京都区部にした理由**: 全国平均の小売価格は公表されておらず、1950年までさかのぼれる長期系列が東京都区部だけのため。
- 統計で確認できない価格（特定チェーンのメニュー価格など）は出題しない。
- **設問は普段の買い物で目にする単位で書く**（1袋・1本・1パック・1杯・1回、肉や魚は店頭の値札と同じ100g）。「1kgあたり」のような業者向けの単位は使わない。
  - 統計が重さ単位の品目は、量が客観的に決まるものだけ身近な量に換算し、設問に量を明記する（もやし1袋＝200g、木綿豆腐1丁＝300g、食パン1斤＝340g（包装食パンの表示ルール）、焼きそば3食入り＝麺450g（調査銘柄の規格））。
  - キャベツ1玉・だいこん1本のように1個の重さが決まらない野菜・果物は、推測値になるため出題しない。

### 1.2 データ項目（`QuestionData`）

| `unit` | string | 単位（`円`） | 返す |

マスターはサーバー側（`server/`）からのみ import する。フロントエンドのコンポーネントからは import しないこと（import するとクライアントバンドルに正解が含まれてしまう）。

### 1.3 生成方法

`src/data/quizMaster.ts` は手で編集せず、[scripts/quiz-data/](../../scripts/quiz-data/README.md) の `run.sh` で生成する（統計ファイルのダウンロード → 東京都区部の年平均の抽出 → 系列の組み立て → TypeScript 出力）。

**系列のつなぎ方**（`build.py`）:

1. 2025年から1年ずつさかのぼり、各年の調査銘柄の単位・内容量を読み取る（例: `袋入り(5kg入り)`、`400g`、`350mL入り,6缶入り`）。
2. 換算のモード（`OVERRIDES[コード].mode`）に従って過去の価格を現在の単位にそろえる。
   - **package**（袋・本・個などの包装単位の既定）: 内容量・入り数が同じ年だけをつなぎ、変わった年より前は使わない。内容量を減らした「実質値上げ」を重さの換算で打ち消さないため（例: のりたまは62g→58g→52gと減っており、52gになった2024年から）。
   - **scale**（1kg・100g などの重さ単位の既定。米・バター・砂糖など量で比べるのが自然な品目にも指定）: 重さ・容量に比例して換算する（例: 米は1971年以前は1kg、1973〜2001年は10kgの価格を5kgに換算）。
   - **unit**: 単位の表記が違うだけで同じ料金・品物の場合（例: はがきの「1枚」と「1通」）。
   - さらに `displayScale` で、統計の単位から設問の量に換算する（例: もやしは1kgあたりの価格 × 0.2 = 200gの価格）。
3. 重さ⇔個数のように換算できない単位の切り替わりがあれば、それより前は使わない（例: 鶏卵は2001年以前が重さ単位のため2002年から）。
4. 品物の種類そのものが変わった時期は、目視レビューで `candidates.py` の `OVERRIDES[コード].minYear` に指定し、それより前を使わない（例: カップ麺は2001年以前が袋めん、豚肉は2014年以前がロース）。
5. 前年比で1.5倍超・0.67倍未満の段差を一覧にして、銘柄変更による段差か実際の値動き（野菜の豊凶、石油ショック等）かを確認する。

当時の調査銘柄が現在と異なるもの（例: 米は2010年以前がブレンド米など）は、コラムに注記する。

### 1.6 出題
- `GET /api/quiz?count=N` で、全100問を Fisher–Yates でシャッフルして N 問を抽出する（カテゴリの均等化は行わない）。
- 2026-10-11 まで使っていた `sort(() => 0.5 - Math.random())` は元の並び順が残り、10問出題でマスター先頭のお米が 23.4%、末尾の品目が約7%の確率で選ばれていた（均等なら10%）。

## 2. 設問スコア・総合スコア

回答値 $A_i$、正解 $T_i$ に対し、相対誤差率を次のように定める。

$$E_i = \frac{|A_i - T_i|}{T_i}$$

$$S_i = \max\left(0, \min\left(100, \text{round}\left(100 \times \left(1 - \frac{E_i}{0.4}\right)\right)\right)\right)$$

誤差 0% で 100点、誤差 40% 以上で 0点になる（線形）。**未回答（時間切れで入力なし）は 0点**とする。総合スコアは出題した $N$ 問（未回答を含む）の平均である。未回答を除いて平均すると、難しい問題をわざと時間切れにして点を上げられるため。

$$\text{TotalScore} = \text{round}\left(\frac{1}{N} \sum_{i=1}^N S_i\right)$$

## 3. 上位何%（パーセンタイル）

これまでの全診断の総合スコア（`score_counts`。生成データを含む）と比べた順位から出す（2026-10-11 まで使っていた正規分布モデル μ=65, σ=16 は廃止）。

今回より前の診断について、自分より高いスコアの人数を $H$、同点の人数を $E$、全体の人数を $M$ とする。自分を含めた順位の中央（同点は真ん中扱い）を割合にする。

$$\text{TopPercentile} = \text{clamp}_{[0.1,\ 100]}\left(\frac{H + (E + 1)/2}{M + 1} \times 100\right)$$

小数1桁に丸める。

| 状況 | 上位 |
| :--- | ---: |
| 比較対象がいない（最初の1人） | 50.0% |
| 500人の中で単独1位 | 0.1% |
| 500人の中で単独最下位 | 99.9% |
| 全員と同点 | 50.0% |

- 総合スコアは出題数（10〜100問）にかかわらず同じ分布で比べる。
- `score_counts` は最大101行なので、診断が増えても読み取り量は一定。

## 4. 物価感覚タイプ判定

平均バイアスは次のとおり（`biasScore`、小数3桁）。

$$\text{Bias} = \frac{1}{N_{\text{回答}}} \sum \frac{A_i - T_i}{T_i}$$

和と $N_{\text{回答}}$ は回答した設問だけで取る（未回答は含めない。1問も回答していなければ 0）。

上から順に判定する。

| コード | タイプ名 | 判定条件 | `biasTendency` |
| :--- | :--- | :--- | :--- |
| `master` | リアルタイム相場マスター | TotalScore ≥ 80 | `balanced` |
| `timeslip` | 過去価格タイムスリップ型 | Bias ≤ -0.08 | `underestimated` |
| `panic` | インフレ過敏型 | Bias ≥ +0.08 | `overestimated` |
| `rough` | 大らか直感型 | 上記以外 | `volatile` |

タイプの文言（`tagline` / `description` / `badgeColor`）は `SENSE_TYPES`（`src/data/quizMaster.ts`）に定義している。

## 5. 回答分布（10分割ヒストグラム）

`generateDistribution()` が、設問ごとに10個のビンを作る。

1. **範囲の決定**
   - 下限: `min(T×0.5, A×0.85, 平均×0.85)`
   - 上限: `max(T×1.5, A×1.15, 平均×1.15)`
   - 未回答のとき（A がない）や、集計対象の回答がなく平均がないときは、その項を除く。
2. **ステップ幅**: `(上限 - 下限) / 10` を「1・2・5・10 × 10^k」のキリの良い値に丸める（最小1円）。
3. **開始点**: 下限をステップ幅で切り捨てた値（最小1円）。
4. **ビン**: 開始点からステップ幅ごとに10個作る。最後のビンは上限なし（`max = Infinity`）。
   - ラベル: 先頭は `〜{開始点+ステップ}円`、末尾は `{min}円〜`、それ以外は `{min}円`。
5. **母集団**: D1 にあるその設問の直近500件に、今回の回答（未回答なら加えない）を加えたもの。集計対象外の回答も含む（コードに書いたモックは使わない。D1 に投入した生成データは含む）。各ビンの `count` と `percent` を出す。
   - ここでの「平均」は [7. 世間平均・最低値・最高値](#7-世間平均最低値最高値) の値。
6. **フラグ**: 各ビンに `hasUserAnswer` / `hasActualPrice` / `hasAverageExpected` を立てる。

注意点として、最初のビンより下の値（開始点未満）はどのビンにも入らない。

### 5.1 表示ルール（面1）

| 該当 | 色 |
| :--- | :--- |
| あなたの回答 | コバルトブルー |
| 正解（公的相場） | リーフグリーン |
| 全体平均 | マスタードイエロー |
| 該当なし | ニュートラルグレー |
| 複数が同じビンに重なる | 該当色の斜めストライプ（`repeating-linear-gradient(45deg, …)`） |

バーの先端には割合（%）だけを表示し、テキストバッジは付けない。

- **レイアウト**: ヘッダー行の左にタイトル「全体の回答分布」、右に凡例（回答 / 正解 / 平均値 / 重なり）を置く。グラフ全体は 290px の固定枠に収める（10行は高さ方向に均等配分）。
- **目盛り（縦グリッド線）**: 0% を基準線（実線）とし、目盛りの最大値までを4等分した位置に点線を引く。グラフ下に目盛りラベルを置く（幅540px以下では両端のみ）。
- **目盛りの最大値**: 最大ビンの割合を20%刻みで切り上げた値（20〜100%）。棒の長さは「割合 / 目盛りの最大値」で、グリッド線と一致する。

## 6. 1単位プロット（面2）

- `rawAnswers` を1円単位で集計し、回答値ごとの人数を縦棒で表す。X軸は「回答があった金額」と「あなたの回答・正解・平均（四捨五入）の金額」を昇順に並べたもの。
- パネル・凡例・配色（回答=青 / 正解=緑 / 平均値=黄 / 重なり=ストライプ / その他=グレー）は面1と共通（`getBarColorClass()` を共有）。
- **目盛り（横グリッド線）**: 0人を基準線（実線）とし、目盛りの最大値までを4等分した位置に点線を引く。目盛りの最大値は、最大人数を4の倍数に切り上げた値（最小4）。
- **棒**: 幅は最大10px（列幅の半分まで）の細い縦棒。棒の上に人数のラベルは出さない（吹き出しと重なって読めなくなるため）。
- 回答0人の基準価格（正解や平均など）は、基準線上の高さ5pxのマーカーで位置だけ示す。
- **棒の選択**: 棒（の列）を押す（マウスはホバー）と、黒い吹き出しで「1,400円 11人」の形で金額と人数を表示する。あなたの回答・正解・平均値に当たる棒は「300円 42人（あなた・正解）」のように付記する。選択中の列は薄く塗る。初期表示はあなたの回答の棒（未回答なら正解の棒）で、横スクロールする場合はその棒が見える位置までずらす。グラフにフォーカスして ←→ キーでも選べる（見えていない棒は見える位置までスクロールする）。
  - タッチはタップで選ぶ。なぞって追従させると横スクロールと取り合うため、なぞる操作では選ばない。
  - 吹き出しは面3と共通（`.chart-tooltip`）。上部に余裕がない場合は下側に出す。見えている範囲（Y軸ラベルの右〜枠の右）からはみ出す分は、描画後に実測して横にずらす（`style.translate`）。横スクロールしたときも合わせ直す。
  - グラフ上の操作は、ボード切り替えのスワイプ・ドラッグとして扱わない。横スクロールできるグラフの上では、トラックパッドの横スクロールでボードを切り替えない。
- 金額の種類が多い場合は、1列48pxを下限として横スクロールにする（Y軸ラベルは左に固定）。
- メトリクスは、あなたの回答、正解、全体平均、中央値の4つ。

## 7. 物価推移（面3）

- `priceHistory`（東京都区部の年平均価格）を折れ線で描く。**実データのみで、補間値は使わない。**
- X軸は年に比例した位置。目盛りラベルは期間に応じて10年・5年・2年・1年ごと（幅640px以下では、10年刻みは20年ごと、1年刻みは1年おきに間引く）。
- 軸・グリッド線・Y軸ラベルは面2（`.vplot-*`）と共用する。
- **目盛り**: 推移幅を約3目盛りに収める「キリの良い」幅（1・2・5×10^k）で4等分し、最小〜最大がすべて入るまで幅を広げる。推移がない（全期間同額）場合は、価格の5%程度の幅で、価格が中ほどに来るようにする。
- **年の選択**: グラフ上を押す・なぞる（マウスはホバー）と、最も近い年の価格を黒い吹き出しで「1973年 1,234円」、最新年は「現在 4,928円」の形で表示する。選択中の年には縦の点線と点を出す。初期表示は最新年。グラフにフォーカスして ←→ キーでも選べる。上部に余裕がない場合は吹き出しを下側に出し、左右端では枠内に寄せる。なぞる操作はボード切り替えのスワイプとして扱わない。
- ヘッダーのピルは「{最古の年}年比」。2倍以上は「約N倍」、それ未満は増減率（%）。
- メトリクスは、あなたの回答、正解、全体平均、最古の年の価格の4つ。
- 100円未満で小数のある価格（例: 1950年の 16.2円）は小数1桁で表示する。

## 7. 世間平均・最低値・最高値

- **集計対象**: 正解の 1/5〜5倍の回答（`server/aggregation.ts` の `isInRange`）。桁の打ち間違いやいたずらの極端な値で、平均が大きく動かないようにする。
- **世間平均（`averageExpected`）**: 集計対象の回答の平均（四捨五入）。今回の回答も対象なら含める。対象が1件もなければ `null`（画面は「—」）。
- **最低値・最高値**: 集計対象の回答の最小・最大。対象がなければ `null`。
- **回答者数（`totalResponses`）**: 集計対象外も含めた回答数。未回答は数えない。
- 値は `item_aggregates`（`in_range_responses`、`sum_answers`、`min_answer`、`max_answer`）から取り、回答ログは読まない。

| 例（正解 200円の品目） | 回答ログ | 回答者数 | 世間平均・最低値・最高値 |
| :--- | :--- | :--- | :--- |
| 180円 | 保存（`in_range = 1`） | 数える | 含める |
| 2,000円（0 を1つ多く打った） | 保存（`in_range = 0`） | 数える | 含めない |
| 99,999,999円 | 保存（`in_range = 0`） | 数える | 含めない |
| 未回答 | 保存しない | 数えない | 含めない |
